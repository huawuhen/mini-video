# 在线充值与短信开通手册（M3-PAY-04）

> **写给谁**：不需要任何编程基础，只要能打开网页、会复制粘贴。
> **做什么**：把「微信支付充值」和「阿里云短信验证码」从零开通到上线。
> **要多久**：各平台审核加起来约 **1~3 周**，其中大部分时间在等审核，实际动手约半天。
> **要花多少钱**：微信服务号认证 300 元/年；短信按条计费（验证码约 0.045 元/条）；微信支付按流水约 0.6% 费率。其余免费。
>
> **两条铁律**（先记住再动手）：
> 1. **所有密钥、证书、AppSecret 只存在服务器上的 `deploy/.env` 文件里**。不发给任何人、不贴进聊天工具、不截图、不提交进代码仓库。需要记录请抄到纸面或密码管理器。
> 2. **真实支付联调（哪怕 1 分钱）和真实短信发送，必须先获得项目所有者的明确授权并写明金额/条数上限**，见文末第 10 章。

## 0. 总览：一共要办这几件事

| # | 事项 | 在哪办 | 前置 |
|---|---|---|---|
| 1 | ICP 备案 | 云服务商备案系统 | 域名、服务器 |
| 2 | 微信服务号 + 认证 | 微信公众平台 | 已备案域名 |
| 3 | 微信支付商户号 | 微信支付商户平台 | 营业执照、法人身份证 |
| 4 | 绑定与域名设置 | 上面两个平台 | 2、3 完成 |
| 5 | API 密钥与证书 | 微信支付商户平台 | 3 完成 |
| 6 | H5 支付申请（可选） | 微信支付商户平台 | 4 完成 |
| 7 | 阿里云短信 | 阿里云控制台 | 阿里云账号 |
| 8 | 填配置 + 重启 + 自检 | 服务器 | 1~7 完成 |

## 1. ICP 备案（约 1~2 周，最先办）

微信支付和服务号都要求网站域名**已备案**，这步没完成后面全办不了。

1. 准备：**域名**（在阿里云/腾讯云等购买，完成「域名实名认证」）+ **云服务器**（购买备案服务码所在厂商的 ECS/轻量应用服务器）+ 营业执照（企业主体备案）。
2. 进入云服务商备案系统（如阿里云「ICP 备案」控制台），按提示填写：主体信息（营业执照）、网站信息（域名、网站名称、服务内容选「其他」或「信息查询服务」类）、负责人信息（法人或经办人身份证 + 人脸核验）。
3. 提交后先过云厂商初审（1~2 天，可能来电核实），再交管局审核（约 1~2 周）。
4. **完成标志**：收到备案成功的短信，且能在[工信部备案系统](https://beian.miit.gov.cn)查到备案号。
5. ⚠️ **备案通过后 30 天内**还要到全国互联网安全管理服务平台（beian.mps.gov.cn）做**公安联网备案**，备案号需挂在网站页脚。

> ⏳ 等待期间可以并行办第 3、7 章（不依赖备案）。

---

## 2. 微信服务号 + 微信认证（约 3~5 天）

用户在微信里充值要走这个服务号（静默授权拿 openid + JSAPI 支付）。

1. 打开 [mp.weixin.qq.com](https://mp.weixin.qq.com) → 立即注册 → 选 **服务号**（订阅号不行）。
2. 用**未注册过公众号的邮箱**注册，主体选企业，填营业执照与管理员信息。
3. 注册完先做 **微信认证**：左侧「设置与开发 → 微信认证」发起，费用 300 元/年，需要营业执照、对公账户打款验证或法人扫脸。
4. **完成后你会拿到（记下来，第 8 章要用）**：
   - 「设置与开发 → 基本配置」页的 **AppID（一串字母数字）** 和 **AppSecret**（点「重置」生成，**只显示一次，立即抄录**）。

---

## 3. 微信支付商户号（约 1~5 天）

1. 打开 [pay.weixin.qq.com](https://pay.weixin.qq.com) → 接入微信支付 → 注册商户号。
2. 主体资料：营业执照、法人身份证、对公账户（个体户可用法人银行卡）、经营场景选「公众号」并填上面第 2 章的 **AppID**（填了还不算绑定完成，见第 4c 章的「关联确认」）。
3. 超级管理员扫码验证、签署在线协议，等审核（可能来电核实经营内容）。
4. **完成后你会拿到**：商户平台登录权限 + **商户号 mchid**（账户中心 → 商户信息，10 位数字）。

---

## 4. 绑定与域名设置（在两个平台各做一次）

### 4a. 服务号：设置网页授权域名

1. 公众平台 → 「设置与开发 → 公众号设置 → 功能设置 → **网页授权域名**」。
2. 填你的站点域名（**不带 https:// ，只填域名**，如 `video.example.com`）。
3. 微信会要求下载一个 `MP_verify_xxxx.txt` 校验文件——把文件名发给运维，放进网站根目录（见 README 的「微信校验文件」一节），再点保存。

### 4b. 商户平台：设置 JSAPI 支付授权目录

1. 商户平台 → 「产品中心 → 开发配置 → **JSAPI 支付授权目录**」→ 添加。
2. 填**顶级域名目录**：`https://你的域名/`（必须是 https，末尾带 `/`）。
   微信按「发起支付页面的目录」校验；本站是单页应用，iOS 微信常按首次进入的页面校验——
   设为顶级域名目录时微信**只校验域名、不校验后面的路径**，对任何入口页面都成立，最稳。
3. 同页的「支付授权域名」若提示需要校验文件，同样转给运维放置。

> 这两处填错的现象：微信里点支付提示「当前页面的 URL 未注册」。回来核对这两条即可。

### 4c. 商户号关联 AppID（让这个服务号能用这个商户号收款）

只在第 3 章填过 AppID 还不够，必须完成「关联确认」这一步，否则下单会报 **appid 和 mch_id 不匹配**：

1. **发起**：微信支付商户平台 → 「产品中心 → **AppID 账号管理** → 关联 AppID」→ 填服务号的 AppID 提交。
2. **确认**：微信公众平台（服务号）→「微信支付 → **商户号管理**」→ 看到待确认的商户号 → 点确认关联。
3. 两边都显示「已关联」才算完成。

---

## 5. API 密钥与证书（商户平台 → 账户中心 → API 安全）

按顺序办三样，每样都抄录好：

1. **APIv3 密钥**：点「设置 APIv3 密钥」→ 自己编一个 **32 位**字母数字串（可用密码生成器）→ 提交。**这是回调解密的钥匙，丢了只能重设**，抄到密码管理器。
2. **商户 API 证书**：点「申请 API 证书」→ 按引导生成 → 下载证书文件。打开压缩包里的 `apiclient_key.pem`（这就是**商户私钥**），全文复制备用；同页能看到**证书序列号**（40 位十六进制），记下。
3. **微信支付公钥**：在「API 安全」页找「**微信支付公钥**」（2024 年后新商户默认就是这种模式，没有的话说明是旧账号，请联系开发）。下载 `wechatpay_public_key.pem` 公钥文件，全文复制；旁边有一行 **公钥 ID**（`PUB_KEY_ID_` 开头），记下。

> 本系统**只支持「微信支付公钥」模式**，不支持旧的平台证书模式；2024 年后开通的商户号默认就是公钥模式，无需额外操作。

## 6. H5 支付申请（可选：让用户在手机自带浏览器里也能付款）

1. 商户平台 → 「产品中心 → 我的产品 → **H5 支付**」→ 申请开通。
2. 填写经营场景时会要 **H5 支付域名**：填你的站点域名（如 `video.example.com`）。
   **必须与站点实际域名完全一致**——付款完成后微信靠页面上的回跳地址把用户送回支付结果页，域名对不上会被微信拒绝或不回跳。
3. 审核通过后：把服务器 `deploy/.env` 里的 `WXPAY_H5_ENABLED` 改为 `true` 并重启。
4. 没申请/没通过也不影响：手机浏览器用户会看到「请在微信中打开本页面充值」的引导。

## 7.（可并行）阿里云短信：RAM 子账号、签名、模板

1. **RAM 子账号**（最小权限，密钥泄露也不至于波及整朵云）：
   阿里云控制台 → 「RAM 访问控制 → 用户 → 创建用户」：勾选「OpenAPI 调用访问」，生成 **AccessKey ID / Secret**（Secret 只显示一次，立即抄录）。
   再给该用户授权：只附加 **`AliyunDysmsFullAccess`**（短信服务）一个策略，别的都不加。
2. **短信签名**：控制台搜「短信服务 → 国内消息 → 签名管理 → 添加签名」：签名用**网站/APP 名称**（与备案主体一致更容易过），上传备案截图作资质。等审核（数小时~2 天）。
3. **短信模板**：「模板管理 → 添加模板」：模板类型选**验证码**，签名选上面通过的，正文示例：
   `您的验证码为${code}，5分钟内有效，请勿泄露于他人。`
   变量**只能有一个 `code`**（系统就传这一个；分钟数写死在正文里，与系统默认有效期 5 分钟一致）。
   ⚠️ 若以后修改了服务器上的 `SMS_CODE_TTL_SECONDS`（验证码有效期），**模板里的分钟数要一起改**，
   而改模板正文需要**重新提交审核**。审核通过后拿到 **模板 CODE**（`SMS_` 开头一串数字）。

## 8. 把拿到的信息填进服务器配置

1. 登录服务器，编辑 `deploy/.env`（对照 `.env.production.example` 里每一行的注释）：

| 你抄录的东西 | 填到哪个变量 |
|---|---|
| 商户号（10 位数字） | `WXPAY_MCHID` |
| `apiclient_key.pem` 全文 | `WXPAY_PRIVATE_KEY` |
| 证书序列号（40 位） | `WXPAY_CERT_SERIAL` |
| 自己设的 32 位 APIv3 密钥 | `WXPAY_APIV3_KEY` |
| `wechatpay_public_key.pem` 全文 | `WXPAY_PUBLIC_KEY` |
| 公钥 ID（PUB_KEY_ID_ 开头） | `WXPAY_PUBLIC_KEY_ID` |
| H5 已开通才改 | `WXPAY_H5_ENABLED=true` |
| `https://域名/api/v1/payments/wechat/notify` | `PAYMENTS_NOTIFY_URL` |
| `https://域名` | `WEB_BASE_URL` |
| 服务号 AppID / AppSecret | `WECHAT_MP_APPID` / `WECHAT_MP_SECRET` |
| 短信 AccessKey ID / Secret | `ALIYUN_SMS_ACCESS_KEY_ID` / `ALIYUN_SMS_ACCESS_KEY_SECRET` |
| 通过的短信签名（一字不差） | `ALIYUN_SMS_SIGN_NAME` |
| 模板 CODE（SMS_ 开头） | `ALIYUN_SMS_TEMPLATE_CODE` |
| 短信启用 | `SMS_PROVIDER=aliyun` |

   私钥/公钥是多行的：粘贴时把换行替换成 `\n` 拼成一行（或在服务器上用编辑器原样多行粘贴亦可）。
2. 同时确认 `ALLOWED_ORIGINS=https://你的域名`、`COOKIE_SECURE=true`（README §8）。
3. 重启：`docker compose up -d`。

### 自检清单（不花一分钱）

```bash
docker compose logs api --tail 200 | grep -E "payments_disabled|sms_aliyun"
curl -s https://你的域名/api/v1/health          # {"ok":true}
curl -s -X POST https://你的域名/api/v1/payments/wechat/notify -d '{}' -H 'Content-Type: application/json'
#  ↑ 期望 4xx 且返回 {"code":"FAIL",...}——说明回调链路通、且验签守卫在工作（不会返回登录页/404）
```
浏览器打开站点 → 钱包 → 在线充值：
- PC 能看到四个金额档位和「微信扫码支付」= 支付配置读通了；
- 缺任何一项时这里会显示「在线充值暂未开放」（检查 api 日志 `payments_disabled_missing_config`，它会点名缺哪个变量）。

## 9. 常见问题速查

| 现象 | 原因与处理 |
|---|---|
| 充值页显示「在线充值暂未开放」 | 有必填项没配齐；看 api 日志 `payments_disabled_missing_config` 点名的变量 |
| 微信里点支付提示「URL 未注册」 | 第 4b 步的 JSAPI 支付授权目录没按顶级域名目录 `https://你的域名/` 填写 |
| 充值页正常，点支付却提示支付暂不可用（日志见 appid / mch_id 不匹配） | 第 4c 步「商户号关联 AppID」没做或只发起未确认：商户平台发起后，还要去公众平台点确认 |
| 授权后回来说「授权未完成」 | 第 4a 步网页授权域名没配/校验文件没放对；或 AppSecret 填错 |
| 微信里付不了、提示需要授权 | 正常引导：点「重新授权」即可；反复失败查 4a 与 AppSecret |
| 手机浏览器付款后停在微信页 | 第 6 章 H5 支付域名与站点域名不一致 |
| 回调一直失败（用户付了钱余额没到） | `PAYMENTS_NOTIFY_URL` 不是 https / 域名没备案 / 被外层代理改写或拦截（外层配置见 README §8：**该路径不得加任何登录、跳转或内容改写**） |
| 收不到验证码 | `docker compose logs api --tail 100` 查 `sms_send_failed`；频控/余额不足会直接给中文原因 |
| 验证码发送失败提示「余额不足」 | 阿里云短信账户余额用完，控制台充值 |

## 10. 真实联调与上线（必须先授权）

- **任何真实支付测试（哪怕 1 分钱）与真实短信发送，必须先获得项目所有者的明确授权，并写明金额/条数上限**（登记到 CODEX_HANDOFF.md §4）。
- 联调只能在 **Ubuntu 生产服务器 + 已备案域名 + HTTPS** 上做（微信回调不认内网地址）。
- 联调建议顺序：发 1 条真实短信 → PC 扫码付最小档位 → 确认钱包到账与「微信支付商户平台 → 交易账单」一致 → 微信内 JSAPI 付最小档位 → （开通 H5 的）手机浏览器付最小档位。
- 全部通过后把 §4 的授权条目标记完成，即可对用户开放充值入口。
