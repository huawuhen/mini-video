## 1. 产品概述

### 1.1 愿景

面向零基础小白、宝妈和家庭记录者的极简 AI 视频生成工具。用户只需写一段想法或生活故事，选好角色、风格和画质，系统自动完成以下流程，用户不需要会剪辑：

**故事理解 → 片段规划 → 角色匹配 → 音画一体生成 → 自动拼接成片**

### 1.2 目标用户

- **核心群体**：宝妈、家庭生活记录者、零基础短视频创作者。
- **特征**：
  - 不懂提示词、Seed、码率等术语，也不想懂；
  - 想记录孩子和家庭日常、做温馨短剧、分享到社交平台；
  - 主要用手机，主要在微信里打开。

### 1.3 核心差异化

1. **我的数字资产库**：用户用自己的照片，借助图片模型生成专属数字人角色卡，永久保存，以后每部作品都能直接调用，尽量保证人物前后一致。
2. **声音前后一致**：平台提供音频素材库（少女、少年、儿童、老人等常用音色），多片段作品中同一角色在每个片段都引用同一段参考音频，避免「上一段和下一段像两个人」。
3. **长片段一次生成**：使用单次可生成约 30 秒、自带多镜头运镜的视频模型（如 wan3.0、seedance2.5），一个片段内部的连贯性由模型保证，减少拼接带来的断裂感。
4. **音画一体**：模型直接输出带环境音、音效和对白的视频，不再单独合成音频，**不加背景音乐和字幕**。
5. **多风格可选**：真人写实、漫剧、卡通 3D 等 6 种常见风格，一键切换。

### 1.4 设计原则

- **零参数**：界面不出现任何技术参数。用户只选「风格」和「画质档位」，一律用中文名、示例图和价格表达；**不让用户选模型、不让用户选时长**。
- **先报价再扣费**：所有收费动作都先展示价格，用户确认后才扣。故事理解免费（平台承担）。
- **永不覆盖**：角色卡、片段重新生成时一律新增一个版本，再切换为选中版本，旧版本保留（在作品保存期内）。

## 3. 端到端流程

```
[① 写故事 + 选角色 + 选风格 + 选画质]  ── 显示「预计 X~Y 元」区间；此时不扣费
        │
        ▼
[② 编剧扩写（仅一句话想法）+ 故事理解 + 片段规划]  用户输入的是剧本 / 脚本时直接理解；只有一句话想法时，pi agent 先按想法、所选风格和时长上限**编剧扩写成剧本**；然后识别角色并匹配角色卡，
        │                 自主决定总时长、片段数量和每段时长（免费，平台承担）
        ▼
◆ 确认点 A：故事确认  ── 展示故事梗概、角色表、「预计成片 N 秒 · 共 M 段」和视频费用；
        │                 可修改文字后重新整理，或直接「确认，下一步」
        ▼
[③ 角色补齐]  故事里有、但本风格还没有形象的角色 → 报价后生成候选角色卡
        │
        ▼
◆ 确认点 B：角色确认  ── 确认每个角色使用的形象；展示**最终精确总价**，
        │                 点「确认并开始制作」时一次性预占余额
        ▼
[④ 音画渲染]  pi agent 把角色卡绑定到各片段并生成最终提示词 → 逐段调用视频模型
        │      （**全部片段按顺序串行生成**，上一段的尾帧作为下一段的参考图；每段生成后做基础技术检查）
        ▼
[⑤ 拼接成片]  按顺序拼接，统一响度，叠加 AI 生成标识，封装 MP4，存七牛，进入作品库
```

### 3.1 确认点规则

- **固定两个确认点**：A 故事确认、B 角色确认，**不提供「全自动，不再询问」开关**（用户 2026-10-16 决定）。其余步骤全自动。
- 确认页的主按钮一次点击就能通过；用户也可以修改后再继续。
- 用户停在确认点时，项目保持「等待确认」状态，可以随时回来继续。**确认点 B 之前不会产生视频费用**。
- 角色全部已有本风格形象时，确认点 B 只展示角色清单和总价，一键通过。
- 在确认点 A 修改故事后点「重新整理」：重新跑故事理解与片段规划（免费，受 9.6 节频率限制）。

### 3.2 生成后的替换（保留原始需求中的「替换/查看」）

- 成片交付后，用户可以查看每个片段，对不满意的片段「重新生成」：先报价、单独扣费，生成为新版本。
- 用户可以在同一片段的多个版本之间切换，切换后重新拼接成片。重新拼接不收费。
- 用户可以修改某个片段的剧情描述后再重新生成。
- 已过期作品（见第 8 节）不能再替换片段。

## 4. 核心功能需求

### 4.1 模块一：我的数字资产库（数字人角色卡）

> 用户 2026-10-16 决定：原「家庭成员」「角色库」统一改名为「我的数字资产库」。当前资产类型为数字人角色卡，以后可扩展其他类型。

**目标**：让同一个人在不同作品、不同片段里尽量保持一致。不对外承诺「完全一致」。

**数据关系**
```
角色（如「宝宝」）
 ├─ 参考照片：用户上传 1~5 张
 └─ 形象（每种风格一个形象，如「真人写实形象」「卡通 3D 形象」）
      └─ 版本：每次生成一个新版本，用户选定其中一个为当前版本
           └─ 角色卡图：定妆正面图 + 多角度/三视图（具体构成在 M0 验证后确定）
```

**功能**
- **创建角色**：填昵称（妈妈、宝宝、爸爸……）、标签（可选）、上传 1~5 张清晰照片（**当前图片模型的参考图上限是 1 张，生成形象只使用第一张，其余照片保存在资产库，换用支持多图的模型后再启用**，用户 2026-10-17 确认）→ 选风格 → 图片模型生成候选角色卡 → 用户选定。
- **无照片创建**：允许只用文字描述（如「5 岁小女孩，短发，爱穿黄色裙子」）生成虚构角色。
- **多风格形象**：同一个角色可以有多个风格的形象。作品选择的风格还没有对应形象时，在第 ③ 步自动生成该风格的候选形象（收费，先报价）。
- **管理**：重命名、更新参考照片、重新生成新版本、切换当前版本、删除角色（删除前提示「已参与 X 部作品，历史作品不受影响」）。
- **存储**：参考照片和角色卡图都存七牛对象存储，**永久保存**在用户账号下，严格按用户隔离，只有本人能访问（私有空间加签名链接）。不受作品 3 个月保存期影响。
- **智能关联**：用户在第 ① 步可以手动勾选角色；故事里出现「宝宝在草地上奔跑」这类文字时，系统自动匹配数字资产库里的「宝宝」，在确认点 A 展示匹配结果，用户可以纠正。

**计费**：生成角色卡按图片模型 SKU 计价，见第 6 节。

### 4.2 模块二：故事理解与片段规划（pi agent）

后台使用 pi agent（`@earendil-works/pi-agent-core`，沿用超搭云已验证的接入方式）作为编剧和导演。**这一步的大模型费用由平台承担，不向用户收费。**

- **输入分两种，处理不同**（用户 2026-10-19 确认）：
  - **剧本 / 脚本 / 较完整的故事**：忠实处理，**不新增对白**，不擅自增加原文没有的人物、道具和场景；
  - **一句话想法**（很短、没有对白和场景描述）：由 pi **编剧扩写**成一份完整剧本——有场景、动作，并且**可以创作对白**——扩写依据是想法本身、用户所选风格和时长上限，长度与情节量要和最终成片时长匹配。扩写是故事理解的第一步，**免费**，与后面的理解和规划一起只计 1 次免费整理次数。
  - 判断方式【默认】：文字很短（**约 60 字以内**，用户 2026-10-19 确定）且没有对白与场景描述时按「想法」处理，否则按「剧本」处理；用户在确认点 A 修改过的文字一律按「剧本」处理，不会再次扩写。
- **故事理解**：提取梗概、角色表、设定集（人物简称与外观、场景、道具）、对白。**确认点 A 展示的是整理后的剧本全文（可编辑）**——想法扩写出来的剧本和用户自己的剧本都在这里确认；补全和扩写的部分必须让用户看到。
- **总时长：由 agent 自主决定**（用户 2026-10-16 决定），用户不选时长。
  - agent 根据故事的信息量和剧情节奏决定总时长与片段数量；
  - 平台设「单部作品最长时长」运营配置项，防止成本失控，初始值 **90 秒**（用户 2026-10-16 确认）（即最多 3 个 30 秒片段），后台可调；
  - 故事内容超出上限时，agent 压缩剧情，并在确认点 A 提示「故事较长，已为您精简为 90 秒」。
- **片段规划**（与故事理解在第 ② 步一起完成，以便确认点 A 就能展示时长和价格）：
  - 片段指一次模型调用的产物，内部可以包含多个镜头和运镜，由模型完成；
  - 每段时长尽量取模型上限（目标 30 秒），agent 可以按剧情节奏决定更短的片段，但时长必须是当前画质档位所映射模型 SKU 支持的取值；
  - agent 为每段输出：剧情描述、镜头和运镜提示、出场角色、对白、环境音描述、时长、与上一段的衔接方式（「接上段尾帧」或「新场景硬切」）。
- **角色绑定**（第 ④ 步开始时）：确认点 B 之后，把每个出场角色替换为选定的角色卡形象，生成最终的视频提示词。只绑定参考图、不改时长，因此不影响已确认的价格。
- **片段间连贯**：同一场景的连续片段，把上一段的尾帧作为下一段的**参考图之一**（视频模型使用「全能参考」模式，同时接收图片与音频参考；尾帧只是普通参考图，连贯程度尽力而为，**不保证首帧级衔接**），与参考音频同时生效。用户 2026-10-17 决定：不追求首尾帧模式（该模式不能引用音频），此冲突暂时忽略；具体效果在 M0 验证。

### 4.3 模块三：音画一体渲染

- 每个片段调用支持原生音画同步、且支持「全能参考」（图片 + 音频参考）的视频模型，参考输入包括：角色卡图、上一段尾帧（可选，作为普通参考图）、音色参考音频、剧情和运镜提示、对白。**上线渠道不绑定 Modelhub**，渠道与模型以 M0 结论为准，适配器按渠道可替换（用户 2026-10-17 决定）。
- 输出带环境音、音效和角色对白的片段。
- 声音前后一致性：作品有 2 个及以上片段时，每个片段都附带出场角色的参考音频，见 4.7。只有 1 个片段时不附带。
- **基础技术检查**（用户 2026-10-19 同意，第一版就做）：每个片段生成并转存后，Worker 用 FFprobe / FFmpeg 做几乎零成本的检查——文件能解码、有视频流、有音频流、时长与请求的时长相差在 ±2 秒内、画幅与分辨率符合预期、不是全黑、画面没有长时间卡住、不是静音。不通过的片段记为失败：作品进入「制作失败」，**已预占的费用保持冻结**，用户可免费点重试（只重新生成失败片段，成功后才结算该段），或取消作品把未结算部分全部退回；失败片段产生的上游成本由平台承担。**不做**「角色像不像」之类的智能检查，也不自动重新生成（智能质检仍属暂缓项）。
- 生成失败：自动重试仅限于「明确未提交成功」的情况。提交结果未知时冻结金额并标记待处理，**不自动重提**，避免重复扣费。
- 上游返回的临时链接必须转存到七牛后，片段才算成功。

### 4.4 模块四：拼接与导出

- 按片段顺序拼接，做响度统一。片段之间一律硬切（「接上段尾帧」只影响生成时的参考图，不做特殊拼接，也不保证画面无缝）。
- **不叠加背景音乐，不加字幕**（用户 2026-10-16 决定）。
- 叠加 AI 生成内容标识：画面显式标识 + 文件元数据隐式标识（法规强制要求，与字幕无关，详见第 11 节合规）。
- 成片规格：MP4（H.264 + AAC），按作品比例（默认 9:16）和画质档位对应的分辨率输出，生成封面图。
- 成片存七牛，进入「我的作品」，开始计算保存期（第 8 节）。

### 4.5 风格选择

第 ① 步用带示例图的风格卡片选择。首批 6 种风格已确认（用户 2026-10-16），示例图由**美工绘制/渲染**（用户 2026-10-20 同意，以美工版本为准，模型出图仅作参考；规格见 `docs/ASSETS.md`）：

| 风格 | 说明 |
|---|---|
| 真人写实 | 接近真实拍摄的家庭影像 |
| 漫剧 | 国漫或短剧漫画风，适合剧情类 |
| 卡通 3D | 类皮克斯 3D 动画，温馨 |
| 日系动漫 | 2D 赛璐璐 |
| 绘本水彩 | 儿童绘本质感 |
| 黏土 / 定格 | 趣味风格 |

- 风格同时决定：角色卡使用哪个风格的形象，以及视频提示词中的风格描述。
- 一部作品只用一种风格。

### 4.6 画质档位

**用户只选画质档位，不选模型**（用户 2026-10-16 决定）。

| 档位（示例） | 用户看到 | 后台映射 |
|---|---|---|
| 标准 | 「标准 · 清晰流畅」+ 单价 | 一个视频 SKU（如某模型 720p） |
| 高清 | 「高清 · 画面更细腻」+ 单价 | 一个视频 SKU（如某模型 1080p） |

- 档位与 SKU 的映射存数据库，运营可在后台调整（例如把「高清」从模型 A 切到模型 B），用户侧无感。
- 档位数量、名称和映射在 M0 测出各模型效果与成本后确定；首期至少提供「标准」「高清」两档。
- 已提交的作品锁定提交时的档位映射和价格版本，后续调整映射不影响进行中的作品；片段重新生成时沿用该作品锁定的映射（若原 SKU 已下架，按当前映射重新报价并提示用户）。
- 接入的视频模型默认支持图片参考和音频参考（用户 2026-10-16 确认），档位映射无需额外区分。

### 4.7 模块五：音频素材库（声音一致）

用户 2026-10-16 新增需求：多个片段分别生成时，同一角色的声音要保持一致。

**素材库内容**（平台提供，所有用户共用）

| 分类 | 首批音色（用户 2026-10-16 确认；每类至少 2 个，方便同类角色区分） |
|---|---|
| 少女 | 温柔少女、元气少女 |
| 少年 | 阳光少年、沉稳少年 |
| 儿童女 | 甜美女童、活泼女童 |
| 儿童男 | 调皮男童、乖巧男童 |
| 青年女 / 青年男 | 知性女声、温暖男声 |
| 中年女 / 中年男 | 慈爱妈妈、沉稳爸爸 |
| 老人女 / 老人男 | 和蔼奶奶、慈祥爷爷 |

- 每个音色包含：中文名、性别、年龄段、一句音色描述、试听音频（5~10 秒）、供模型引用的参考音频（存七牛，平台永久保存）。
- 首批为普通话。音频素材由平台运营上传（AI 生成或网络免费资源），可在后台增删、排序、上下架。

**使用规则**
- **试听**：在资产库「声音」页和确认点 B 都可以点播放试听。
- **用户选择**：在确认点 B，每个角色一行同时显示「形象」和「声音」，用户可以点开更换声音。
- **自动引用**：用户没有选择时，pi agent 按剧本中角色的性别、年龄和性格自动匹配音色，在确认点 B 预先填好并标注「AI 推荐」。同一部作品中不同角色不使用同一个音色。
- **只有 1 个片段时不引用**：模型一次生成的片段内部声音本来就一致（例如 wan3.0 一次生成 30 秒），确认点 B 不显示「声音」列，渲染时也不附带参考音频。
- **2 个及以上片段**：每个片段调用视频模型时，附带本段出场角色的参考音频。
- **锁定**：确认点 B 确认后，本作品的「角色 → 音色」对应关系锁定；之后重新生成片段沿用同一音色。
- 数字资产可以设置「默认声音」（用户 2026-10-16 确认）：设置后，以后的作品自动使用这个声音，用户仍可在确认点 B 更换。
- **计费**：引用音频素材本身免费。上游模型带参考音频的价格如果更高，通过 SKU 体现（见 6.2），并计入确认点 B 的精确报价。
- **技术前提**：接入的视频模型（如 wan3.0、seedance2.5）默认支持同时接收图片参考和音频参考（用户 2026-10-16 确认）。M0 只验证多片段的声音一致效果，不再验证是否支持。

## 6. 计费

### 6.1 原则

- 先充值余额，再按作品预估扣费。金额一律用整数「分」（CNY）。充值方式：兑换码（M2 起）、易支付在线充值（M3，见 6.4）。
- 流程为「报价 → 预占 → 按实际成功结果结算 → 失败部分退回」，全部通过事务账本完成。
- **故事理解与片段规划免费**，LLM 成本由平台承担（只做内部成本核算）。
- 重新拼接、切换片段版本、下载免费。

### 6.2 计价 SKU

每个接入的模型 API，在数据库中按「模型 × 分辨率 ×（其他影响成本的维度）」建立计价 SKU。

| 字段 | 说明 |
|---|---|
| `sku_code` | 如 `video.wan3.720p`、`video.seedance25.1080p`、`image.xxx.2k`、`llm.xxx` |
| 模型 / 渠道 | 对应的上游模型和接入渠道 |
| 类型 | 视频 / 图片 / LLM |
| 分辨率 | 480p / 720p / 1080p…（图片为尺寸档位） |
| 计价单位 | 视频：每秒；图片：每张；LLM：每千 token |
| 售价（分/单位） | 用户价，整数分；**LLM 类 SKU 售价固定为 0** |
| 成本价（分/单位） | 内部核算用，不对用户展示 |
| 支持的时长取值 | 视频专用，如 5/10/15/30 秒，供 agent 规划片段时使用 |
| 是否含原生音频 | 有音频与无音频价格不同时，拆成两个 SKU |
| 参考音频计价 | 视频专用；模型默认支持参考音频，仅当带参考音频的价格不同时，拆成两个 SKU（见 4.7） |
| 状态 / 生效时间 / 价格版本 | 调价时新增版本，不修改旧记录 |

另设「画质档位映射表」：档位 → 视频 SKU，带生效时间与版本（见 4.6）。

### 6.3 报价公式

```
作品总价 = Σ(片段时长秒 × 档位映射视频 SKU 单价)
        + 新生成的角色卡张数 × 图片 SKU 单价
        （故事理解费用 = 0，平台承担）
```

- **第 ① 步**：显示价格区间「预计 X~Y 元」。【默认】下限按 1 个 30 秒片段估算，上限按「单部作品最长时长」估算；角色卡费用按「本风格缺形象的已勾选角色数」估算。不扣费。
- **确认点 A**：片段规划已完成，显示精确的视频费用。
- **确认点 B**：加上需要新生成的角色卡费用，得到**最终精确总价**；用户点「确认并开始制作」时锁定价格版本并**一次性预占**。
- 第 ③ 步生成角色候选时单独报价扣费（角色卡永久归入我的数字资产库，即使作品之后取消也不退）。
- 报价锁定后如果调价，需要用户重新确认，不会静默多扣。
- 余额不足：停在当前确认点，充值后继续。
- 片段重新生成、角色卡重新生成：单独报价、单独扣费。

### 6.4 充值与支付（易支付）

用户 2026-10-17 决定：支付接口使用**易支付**（官网 `https://www.ezfp.cn`，开发文档 `https://www.ezfp.cn/doc/index.html`），采用 **V2 接口**（RSA 签名，`SHA256WithRSA`）。M2 内测期仍只用兑换码充值，在线支付随 M3 上线。

**用户流程**
1. 钱包页点「充值」→ 选充值金额（预设档位）→ 选支付方式（支付宝 / 微信支付）→ 确认。
2. 服务端创建充值订单并向易支付下单，前端按返回的方式展示：跳转收银页，或在 PC 上展示二维码。
3. 支付完成后回到「充值结果页」。页面**不信任浏览器同步跳转**，只轮询我们自己的订单状态（每 2 秒、最长 2 分钟）；到账后显示新余额，超时提示「支付结果确认中，到账后余额会自动更新」。
4. 钱包流水显示「充值 +X 元」；余额不足时的「去充值」入口（确认点 B、重新生成等）充值完成后回到原页面。

**订单与到账规则**
- 金额一律整数「分」。易支付的 `money` 是「元」字符串（最多 2 位小数），只在系统边界用整数运算转换，禁止浮点。
- 商户订单号 `out_trade_no` 使用我方订单 ID；易支付返回的平台订单号 `trade_no`、接口订单号 `api_trade_no` 一并记录。
- **入账条件（缺一不可）**：① 异步通知验签通过（平台公钥）；② `trade_status` 等于 `TRADE_SUCCESS`；③ `pid` 是本商户；④ 通知里的金额与订单金额一致；⑤ 主动调用「订单查询」确认状态为已支付且金额一致（双重核验）；⑥ 通知时间戳在容许范围内（【默认】±10 分钟）。满足后在**一个事务**里把订单置为已支付并入账（账本类型 `recharge`），重复通知不重复入账。
- **回调应答**：处理成功（包括已处理过的重复通知）返回纯文本 `success`；验签失败、金额不符等返回非 success，并写审计日志。
- **对账补偿**：定时任务查询超过 5 分钟仍未到账的订单：平台显示已支付则补入账；未支付且超过有效期则关闭订单（调用关单接口，部分渠道不支持则只在本地置为过期）。
- 订单有效期【默认】30 分钟。**过期后用户才完成支付的，只要平台确认已收款，仍然入账**。
- 防滥用：每用户同时最多 3 笔待支付订单、每小时最多创建 10 笔；下单带上用户真实 IP（`clientip`）。
- 充值预设金额 **50 / 100 / 500 / 1000 元**（用户 2026-10-20 确定），单笔上限 1000 元，后台可调；**充值 1:1 到账，暂无赠送**，支付手续费由平台承担。
- 支付方式：本期开放支付宝、微信支付，后台可开关；易支付还支持 QQ 钱包、网银、PayPal、USDT、Stripe 等，本期不开放。
- 终端：手机和 PC 浏览器使用「统一下单」接口，按设备类型让平台返回跳转链接或二维码。**微信 / 支付宝内置浏览器的 JSAPI 支付（需要用户 openid）和小程序支付本期不做**（随「微信环境限制」【暂缓】），这些环境提示「请在系统浏览器中打开后再充值」。
- 密钥：商户 ID、商户私钥、平台公钥只放服务端环境变量。仓库是公开的，**严禁提交**，日志也不记录私钥和签名。
- 可用性：易支付是第三方平台，通道开通、费率、结算周期以其商户后台为准。平台不可用时充值页提示「充值暂时不可用」，兑换码仍可用。

**退款**：易支付提供退款接口（需在商户后台开启开关，部分渠道不支持部分退款）。但「充值退款政策」属于「退款与售后细则」【暂缓】：本期不提供用户自助退款，客服在运营后台人工处理，账本记 `adjust` 并留审计。

**易支付接口要点（实现依据）**

| 能力 | 地址（相对 `EZFP_BASE_URL`，默认 `https://www.ezfp.cn`） | 用途 |
|---|---|---|
| 统一下单 | `POST /api/pay/create` | 服务端下单，返回 `trade_no`、`pay_type`（`jump` / `html` / `qrcode` / `urlscheme` 等）、`pay_info`；`method` 取 `web`，`device` 取 `pc` 或 `mobile` |
| 页面跳转支付 | `POST /api/pay/submit` | 备选：不需要服务端拿二维码时用表单跳转 |
| 订单查询 | `POST /api/pay/query` | 双重核验与对账；支付状态 0 未支付、1 已支付、2 已退款、3 已冻结、4 预授权 |
| 订单关闭 | `POST /api/pay/close` | 过期订单关单（部分渠道不支持） |
| 退款 / 退款查询 | `POST /api/pay/refund`、`/api/pay/refundquery` | 人工退款时使用 |
| 异步通知 | 平台以 **GET** 请求我方 `notify_url` | 必须返回 `success`；验签要兼容平台以后新增的字段 |

- 请求为 `application/x-www-form-urlencoded`，响应为 JSON，编码 UTF-8；每个请求带 10 位秒级 `timestamp`、`sign`、`sign_type=RSA`。
- 签名：取所有非空参数（不含 `sign`、`sign_type`、数组和文件），按键名 ASCII 升序排列，拼成 `参数=参数值&…`，用商户私钥做 `SHA256WithRSA`。响应和异步通知用平台公钥验签。
- 以下细节文档没有写明，**必须在沙箱用小额真实订单验证**后固化：签名的输出编码（预期 base64）、密钥格式（预期 PEM）、待签名字符串里的值是否 URL 编码（预期不编码）、`out_trade_no` 的长度和字符限制、通知时间戳的容许范围。验证前不得上线。

## 7. 项目状态机

```
draft（草稿）
 → understanding（故事理解 + 片段规划中）
 → story_review（◆A 等待确认）
 → casting（角色补齐中）
 → cast_review（◆B 等待确认）
 → rendering（角色绑定 + 渲染中，片段级子状态）
 → composing（拼接中）
 → delivered（已交付）
 → expired（已过期，视频文件已清理）

story_review → understanding（用户修改故事后重新整理）
任意进行中阶段 → paused（用户暂停）→ 恢复原阶段
任意阶段 → failed（可从失败步骤续跑）/ canceled
片段子状态：queued → submitting → generating → succeeded / failed / unknown（提交结果未知，冻结金额）
```

与 v1 的区别：去掉独立的 `planning` 状态（并入 `understanding`）；新增 `expired`；余额不足不再进入 `paused`，而是停在确认点 B。

## 8. 存储与保存期

- 对象存储统一使用**七牛 Kodo**：参考照片、角色卡图、音频素材、片段视频、成片、封面。
- 上游模型返回的临时链接，必须转存到七牛后才算成功。
- 私有资源使用签名链接访问，按用户隔离。

### 8.1 保存期限

| 资源 | 保存期 |
|---|---|
| 角色参考照片、角色卡图（全部版本） | **永久** |
| 平台音频素材（试听与参考音频） | 永久（下架后不再展示，已引用的作品不受影响） |
| 成片、片段视频（含未选中版本） | **3 个月**（用户 2026-10-16 决定） |
| 作品记录：标题、封面、故事文字、片段规划 | 永久（用于「已过期」展示和「再做一部」） |

【默认】细则：
- 起算时间：作品首次交付时间。之后替换片段并重新拼接，**不延长**保存期（规则简单、成本可控）。
- 到期后由 Worker 定时任务删除七牛上的成片与片段视频文件，作品状态改为 `expired`；封面图保留。
- 提醒：交付页常驻保存期提示条；到期前 7 天起「我的作品」显示倒计时并弹一次提醒。微信公众号、短信等站外通知随「微信环境限制」【暂缓】。
- 用户主动删除作品：立即删除该作品的视频文件，不影响角色资产。

## 9. 非功能需求

1. **零门槛容错**：不暴露技术参数；输入过短时自动补全，并在确认点 A 让用户过目。
2. **异步队列与恢复**：长耗时流程走任务队列；页面刷新、关闭、切后台后，用户从「我的作品」恢复查看进度。
3. **隐私隔离**：用户之间的资产严格隔离；家庭和儿童照片只用于该用户自己的角色卡和作品生成。
4. **账本正确性**：任何失败都不会多扣费；提交结果未知时冻结金额，等待人工或对账处理。
5. 【待确认】性能目标：如 30 秒成片从提交到交付不超过 X 分钟（M0 实测后定）。
6. **免费环节防滥用**：故事理解免费，需要限制频率，防止被刷 LLM 成本。【默认】每个账号每天最多发起 20 次故事理解（含「重新整理」），上限可在后台配置；超出后提示「今天的免费整理次数已用完，明天再来」。
